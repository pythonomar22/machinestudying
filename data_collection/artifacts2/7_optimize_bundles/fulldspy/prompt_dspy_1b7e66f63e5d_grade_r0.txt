0032: class BetterTogether(Teleprompter):
0033:     """A meta-optimizer that combines prompt and weight optimization in configurable sequences.
0034: 
0035:     BetterTogether is a meta-optimizer proposed in the paper
0036:     [Fine-Tuning and Prompt Optimization: Two Great Steps that Work Better Together](https://arxiv.org/abs/2407.10930).
0037:     It combines prompt optimization and weight optimization (fine-tuning) by applying them in a
0038:     configurable sequence, allowing a student program to iteratively improve both its prompts and
0039:     model parameters.
0040: 
0041:     The core insight is that prompt and weight optimization can complement each other: prompt
0042:     optimization can potentially discover effective task decompositions and reasoning strategies,
0043:     while weight optimization can specialize the model to execute these patterns more efficiently.
0044:     Using these approaches together in sequences (e.g., prompt optimization then weight optimization)
0045:     may allow each to build on the improvements made by the other. Empirically, this approach often
0046:     outperforms either strategy alone, even with state-of-the-art optimizers. For example, a
0047:     [Databricks case study](https://www.databricks.com/blog/building-state-art-enterprise-agents-90x-cheaper-automated-prompt-optimization)
0048:     shows that combining BetterTogether with GEPA and fine-tuning outperforms either approach
0049:     alone.
0050: 
0051:     The optimizer is initialized with a metric and custom optimizers. For example, you can combine
0052:     GEPA for prompt optimization with BootstrapFinetune for weight optimization:
0053:     ``BetterTogether(metric=metric, p=GEPA(...), w=BootstrapFinetune(...))``. The ``compile()``
0054:     method takes a student program, trainset, and strategy string where strategy keys correspond
0055:     to the optimizer names from initialization. It executes each optimizer in the specified sequence.
0056:     When a validation set is provided, the best performing program is returned; otherwise, the
0057:     latest program is returned. Note: Weight optimizers like BootstrapFinetune require student
0058:     programs to have LMs explicitly set (not relying on global dspy.settings.lm), and BetterTogether
0059:     mirrors this requirement for simplicity. Therefore we call ``set_lm`` before compiling.
0060: 
0061:         >>> from dspy.teleprompt import GEPA, BootstrapFinetune
0062:         >>>
0063:         >>> # Combine GEPA for prompt optimization with BootstrapFinetune for weight optimization
0064:         >>> optimizer = BetterTogether(
0065:         ...     metric=metric,
0066:         ...     p=GEPA(metric=metric, auto="medium"),
0067:         ...     w=BootstrapFinetune(metric=metric)
0068:         ... )
0069:         >>>
0070:         >>> student.set_lm(lm)
0071:         >>> compiled = optimizer.compile(
0072:         ...     student,
0073:         ...     trainset=trainset,
0074:         ...     valset=valset,
0075:         ...     strategy="p -> w"
0076:         ... )
0077: 
0078:     You can pass optimizer-specific arguments to each optimizer's ``compile()`` method using
0079:     ``optimizer_compile_args``. This allows you to customize each optimizer's behavior:
0080: 
0081:         >>> from dspy.teleprompt import MIPROv2
0082:         >>>
0083:         >>> # Use MIPROv2 for prompt optimization with custom parameters
0084:         >>> optimizer = BetterTogether(
0085:         ...     metric=metric,
0086:         ...     p=MIPROv2(metric=metric),
0087:         ...     w=BootstrapFinetune(metric=metric)
0088:         ... )
0089:         >>>
0090:         >>> student.set_lm(lm)
0091:         >>> compiled = optimizer.compile(
0092:         ...     student,
0093:         ...     trainset=trainset,
0094:         ...     valset=valset,
0095:         ...     strategy="p -> w",
0096:         ...     optimizer_compile_args={
0097:         ...         "p": {"num_trials": 10, "max_bootstrapped_demos": 8},  # Configure MIPROv2's compile arguments
0098:         ...     }
0099:         ... )
0100: 
0101:     Since BetterTogether is a meta-optimizer that can run arbitrary optimizers in sequence, any
0102:     sequence of optimizers can be combined together. The optimizer names used in the strategy string
0103:     correspond to the keyword arguments specified in the constructor. For example, different prompt
0104:     optimizers can be alternated multiple times (though note this is just an illustration of
0105:     BetterTogether's flexibility, not a recommended configuration):
0106: 
0107:         >>> from dspy.teleprompt import MIPROv2, GEPA
0108:         >>>
0109:         >>> # Chain two optimizers three times: MIPROv2 -> GEPA -> MIPROv2
0110:         >>> optimizer = BetterTogether(
0111:         ...     metric=metric,
0112:         ...     mipro=MIPROv2(metric=metric, auto="light"),
0113:         ...     gepa=GEPA(metric=metric, auto="light")
0114:         ... )
0115:         >>>
0116:         >>> student.set_lm(lm)
0117:         >>> compiled = optimizer.compile(
0118:         ...     student,
0119:         ...     trainset=trainset,
0120:         ...     valset=valset,
0121:         ...     strategy="mipro -> gepa -> mipro"
0122:         ... )
0123: 
0124:     Note:
0125:         Output Attributes: The returned program includes two additional attributes:
0126:         ``candidate_programs`` and ``flag_compilation_error_occurred``. The ``candidate_programs``
0127:         attribute is a list of dicts, each containing 'program', 'score', and 'strategy' (e.g.,
0128:         '', 'p', 'p -> w', 'p -> w -> p'), sorted by descending score (similar to
0129:         ``dspy.MIPROv2.candidate_programs``). If any optimizer step fails,
0130:         ``flag_compilation_error_occurred`` is set to True and the best program found so far is
0131:         returned.

0134:         (launching, killing, and relaunching after fine-tuning), which are no-ops for most

0136:         BootstrapFinetune with local providers (e.g., dspy.LocalProvider), as it handles model
0137:         initialization and cleanup between optimization steps.
