- Label: `lm_provider_integration_and_configuration`
- Question: `If I declare an output as `dspy.Reasoning`, when does DSPy turn on a provider’s native reasoning mode, and what cases deliberately disable that path even though the field is present?`
- Gold answer:
A `dspy.Reasoning` output field turns on native reasoning only if the LM supports reasoning and `reasoning_effort` is not `None`; if you did not set it, DSPy defaults it to `'low'`. DSPy deliberately skips the native path when `reasoning_effort=None`, when `lm.supports_reasoning` is false, or when the model name contains `gpt-5` while using chat mode. In the native path, the reasoning field is removed from the parsed signature and later filled from `reasoning_content` in the LM response.
