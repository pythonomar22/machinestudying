Which return shapes preserve DSPy’s prediction bookkeeping, and which runtime features disappear if I bypass the standard invocation path?`
- Gold answer:
The outer runtime logic lives in `Module.__call__` and `Module.acall`, not in the implementation body itself. That path applies callbacks, pushes `caller_modules` context, and, when usage tracking is enabled, only attaches LM-usage totals if the module returns either a `dspy.Prediction` or a tuple whose first element is a `Prediction`; other return shapes still run, but they cannot carry that bookkeeping. Bypassing the normal call path skips that wrapper entirely.
