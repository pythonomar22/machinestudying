- Question: `I saved an embeddings-based retriever and later reloaded it without wanting to recompute the corpus matrix. Which pieces are persisted, what do I still have to supply, and how does DSPy avoid rebuilding the embeddings?`
- Gold answer:
DSPy saves the corpus-side retriever state: `k`, `normalize`, the corpus text, the embedding matrix, and a FAISS index file when one exists. You must supply an `embedder` again on load because callables are not serialized. `Embeddings.from_saved()` avoids recomputing corpus embeddings by bypassing `__init__`, restoring `search_fn`, and then calling `load()`.
```python
import tempfile, numpy as np
from dspy.retrievers.embeddings import Embeddings

def embed(texts):
    rows = []
    for text in texts:
        rows.append(np.array([1, 0], dtype=np.float32) if 'cat' in text else np.array([0, 1], dtype=np.float32))
    return np.stack(rows)

r = Embeddings(['cat doc', 'dog doc'], embed, k=1)
with tempfile.TemporaryDirectory() as td:
    r.save(td)
    r2 = Embeddings.from_saved(td, embed)
    print(r2.k, r2.normalize, r2.corpus)
    print(r2('dog').passages)
```
